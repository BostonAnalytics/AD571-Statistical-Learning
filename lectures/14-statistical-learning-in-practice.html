21  Statistical Learning in Practice

Author

Nakul R. Padalkar

Modified

June 12, 2026

The final chapter brings the course together around reproducible analysis, communication, model limitations, and responsible use. A good statistical learning project is not a list of fitted models. It is a defensible workflow from question to data to evidence to decision.

21.1 Learning Objectives

  • Describe a complete statistical learning workflow.
  • Communicate model performance, uncertainty, and limitations.
  • Identify reproducibility risks in notebooks and ad hoc analyses.
  • Compare models using evidence matched to the project goal.
  • Connect classical statistical learning habits to modern machine learning practice.

21.2 The Complete Workflow

A complete project should make each of these choices visible:

  1. research or prediction question,
  2. observational unit and response variable,
  3. candidate predictors and data exclusions,
  4. preprocessing and feature engineering,
  5. train/validation/test design,
  6. candidate model classes,
  7. tuning strategy,
  8. final evaluation,
  9. interpretation and uncertainty,
  10. limitations and maintenance plan.

The workflow matters because most modeling failures are not caused by a single bad algorithm. They are caused by unclear targets, leakage, unstable preprocessing, poorly matched evaluation metrics, or overconfident interpretation.

21.3 Choosing Evidence

Different goals require different evidence:

Goal Evidence to emphasize
Accurate prediction Held-out error, calibration, robustness
Explanation Coefficients, uncertainty, diagnostics, design limitations
Screening Sensitivity, specificity, threshold costs
Ranking ROC/AUC, precision-recall, lift
Segmentation Cluster stability, profiles, external validity
Communication Simplicity, visuals, reproducibility

The final model should be justified using the evidence that matches the goal, not the metric that makes the model look best.

21.4 Simulation as Practice

Monte Carlo simulation complements predictive modeling by propagating uncertainty through a decision model. Instead of reporting one static outcome, simulation reports a distribution of possible outcomes.

  • R
  • Python
simulate_profit <- function(n, price, unit_cost, demand_mean, demand_sd) {
  demand <- pmax(0, rnorm(n, mean = demand_mean, sd = demand_sd))
  revenue <- price * demand
  cost <- unit_cost * demand
  revenue - cost
}

set.seed(571)
profit <- simulate_profit(
  n = 10000,
  price = 40,
  unit_cost = 25,
  demand_mean = 1000,
  demand_sd = 150
)

quantile(profit, c(0.05, 0.5, 0.95))
import numpy as np

def simulate_profit(n, price, unit_cost, demand_mean, demand_sd, seed=571):
    rng = np.random.default_rng(seed)
    demand = np.maximum(0, rng.normal(demand_mean, demand_sd, n))
    revenue = price * demand
    cost = unit_cost * demand
    return revenue - cost

profit = simulate_profit(
    n=10000,
    price=40,
    unit_cost=25,
    demand_mean=1000,
    demand_sd=150
)

print(np.quantile(profit, [0.05, 0.5, 0.95]))

Simulation does not remove uncertainty. It makes uncertainty visible enough to reason about tradeoffs, tail outcomes, and risk tolerance.

21.5 Reproducible Reporting

A reproducible report should allow another analyst to rerun the work and understand the decisions. It should include:

  • package versions or computing environment,
  • data source and cleaning rules,
  • random seeds for resampling,
  • train/test split definition,
  • model formulas or tuning grids,
  • final evaluation code,
  • clear tables and figures,
  • limitations written in ordinary language.

Reproducibility is also a communication practice. A reader should be able to distinguish observed data patterns, modeling assumptions, validation evidence, and recommendations.

21.6 Responsible Interpretation

Models can encode bias, fail under distribution shift, and invite overconfident decisions. A final report should state:

  • what population the data represent,
  • what cases are excluded or underrepresented,
  • whether the task is predictive or causal,
  • which errors are most costly,
  • where the model should not be used,
  • how performance should be monitored over time.

Responsible statistical learning means treating a model as an evidence-producing tool, not as an authority.

21.7 Final Project Structure

A strong final project uses the following structure:

  1. question and motivation,
  2. data description,
  3. exploratory analysis,
  4. preprocessing and splitting,
  5. candidate models,
  6. validation results,
  7. final model and held-out evaluation,
  8. interpretation,
  9. limitations,
  10. conclusion.

The conclusion should be short and specific: what was learned, how strong the evidence is, and what decision or next analysis follows.
